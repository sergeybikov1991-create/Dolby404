## Зафиксированный сценарий запуска
1. При запуске приложение проверяет сохранённую Supabase-сессию.
2. Наличие локального токена само по себе не считается достаточным: пользователь дополнительно проверяется через серверный `auth.getUser()`.
3. Если сервер подтвердил авторизацию, приложение показывает промежуточный экран:
   - «Вы уже зашли»
   - кнопка «Продолжить»
   - подсказка о свайпе справа налево.
4. Кнопка «Продолжить» и свайп справа налево открывают главную страницу `home.html`.
5. Если действительной сессии нет, показывается обычное приветствие с переходом к регистрации/авторизации.
6. Если сеть недоступна, показывается отдельный экран ошибки сети; сохранённая сессия не сбрасывается и пользователя не отправляет на регистрацию.

## Правила сохранения эталона
- Считать этот сценарий базовой неизменяемой реализацией приветствия и авторизации APK 2.0.
- Не возвращать автоматический показ регистрации уже авторизованному пользователю.
- Не считать наличие локальной записи сессии доказательством авторизации без серверной проверки.
- Не сбрасывать сессию из-за временной сетевой ошибки.
- Дальнейшие изменения запуска, приветствия и авторизации выполнять поверх этого эталона, не ломая подтверждённое поведение.
- Изменения относятся только к ветке `APK-2.0`; сайт и основной Android Messenger не менять.
- Это эталон отдельного WebShell Test APK, а не production APK основного мессенджера.
